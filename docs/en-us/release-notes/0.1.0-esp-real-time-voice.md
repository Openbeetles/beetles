# Beetle OS 0.1.0-esp-real-time-voice Release Notes

[Back to English docs](../README.md)

This release updates Beetle OS from `0.1.0-chat` to
`0.1.0-esp-real-time-voice`. The focus of this version is the ESP realtime
voice experience: wake word detection, microphone capture, realtime dialogue,
audio playback, and browser-based updates.

## Highlights

- Added ESP WakeNet wake word support for ESP32-S3 and ESP32-P4 boards.
- Added the realtime voice session flow after wake, including voice input,
  server-side voice detection, audio response playback, and idle exit.
- Added ESP audio codec support for the ES7210 input path and ES8311 output
  path, with board-level audio bus configuration.
- Added Configure UI controls and validation for audio, I2C, bus, and hardware
  settings used by the voice path.
- Added WakeNet model assets to browser firmware bundles. Browser updates can
  now write the model partition together with the firmware.
- Added display HUD v2 surfaces for device status, voice mode, resource state,
  and recovery state.
- Improved ESP resource scheduling during voice sessions so voice, display,
  background write-back, and external connections are less likely to interfere
  with each other.

## Voice And Wake

This version brings the ESP voice path into the product build. WakeNet loads the
packaged speech model from device flash, listens for the wake word through the
board microphone input, and starts a realtime voice session after wake.

After wake, Beetle OS opens a realtime voice session with the configured voice
provider. The device streams microphone audio, plays returned voice replies,
and exits voice mode automatically after the conversation has been idle.

## Browser Flashing

The browser firmware package now includes segmented update files for each board
profile:

- application image
- bootloader
- partition table
- WakeNet model image

This means browser-based update can install both the firmware and the speech
model used by WakeNet. Users do not need to flash the model manually when using
the packaged browser update flow.

## Upgrade Notes

This release introduces a model partition. Devices upgrading from `0.1.0-chat`
cross a partition layout change because the model partition uses space that was
previously part of storage.

Users should choose the flashing method that matches their upgrade intent:

- Use browser update when you want to preserve existing device storage and
  update the firmware plus WakeNet model through the packaged update flow.
- Use a full installation when you need a clean partition layout. A full
  installation clears device configuration, so Wi-Fi and service settings must
  be configured again afterward.

Back up or record important device settings before choosing a full
installation.

## Runtime And Display

While voice is active, Beetle OS prioritizes microphone capture, the realtime
connection, and audio playback. Some background write-back, external reconnect,
and heavy display refresh work may be delayed to reduce the chance of
interrupting the voice path.

The display HUD v2 update makes the device state easier to inspect during boot,
configuration, voice, recovery, and normal operation.

## Stability Improvements

This version adds protections around the ESP voice and update flows:

- Browser update bundles include the WakeNet model to keep firmware and model
  versions aligned.
- Terminal flashing defaults to configuration-preserving update mode.
- Full installation is an explicit choice, reducing the risk of accidental
  configuration loss.
- Background work is less likely to interfere with realtime voice sessions.
- Device state and voice mode are easier to inspect on the display surface.

## Compatibility

- Firmware bundles are generated for the ESP board profiles shipped by this
  branch, including ESP32-S3 and ESP32-P4 profiles.
- Realtime voice requires a configured realtime voice provider and working
  network access.
- Existing text channel, Configure UI, display, and memory features remain part
  of the product surface.
